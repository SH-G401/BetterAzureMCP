# What users complain about in the official Azure MCP Server

_Collected 2026-09-25 from Microsoft's issue trackers ([microsoft/mcp](https://github.com/microsoft/mcp), the archived [Azure/azure-mcp](https://github.com/Azure/azure-mcp)), GitHub Community discussions, Microsoft Q&A, security advisories and independent reviews. Several article sites could not be opened from the research environment; for those, the summary relies on search-engine excerpts, which is noted where it applies._

Each complaint is mapped to where BetterAzureMCP stands today: **Solved** (by design, with the mechanism named), **Partly** or **Gap**. The last section turns the gaps into work items.

## 2. Sign-in

| Complaint                                                                                                                                                                                                                                                                    | Evidence                                                                                                        | BetterAzureMCP                                                                                                                                                                                                        |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Versions 0.6–0.8 skipped Azure CLI credentials and fell back to an interactive browser login. On headless Linux, WSL, Docker and CI this printed "No X display available" into the JSON-RPC stream and caused **4-minute request timeouts**. Workaround: downgrade to 0.5.8. | [microsoft/mcp#776](https://github.com/microsoft/mcp/issues/776)                                                | **Solved.** The credential chain has no interactive credentials at all. A missing login returns an error within milliseconds. Nothing but protocol messages can reach stdout (stdout guard plus an integration test). |
| Copilot Agent mode "always prompting login" even though `az login` works in the terminal.                                                                                                                                                                                    | [microsoft/mcp#401](https://github.com/microsoft/mcp/issues/401)                                                | **Solved.** No prompts, ever. A later `az login` is picked up without restarting the client.                                                                                                                          |
| "Fails to auth even though I have run `az login`" (Kusto).                                                                                                                                                                                                                   | [microsoft/mcp#1105](https://github.com/microsoft/mcp/issues/1105)                                              | **Partly.** `azure_context` and `doctor` show which account, tenant and credential are used, which exposes the usual cause (wrong tenant). Kusto itself is not in scope.                                              |
| `InteractiveBrowserCredential` thrown inside Docker.                                                                                                                                                                                                                         | [microsoft/mcp#710](https://github.com/microsoft/mcp/issues/710)                                                | **Solved** (no interactive credentials).                                                                                                                                                                              |
| `AZURE_TOKEN_CREDENTIALS` not respected.                                                                                                                                                                                                                                     | [microsoft/mcp#1030](https://github.com/microsoft/mcp/issues/1030)                                              | **Solved.** One documented setting (`BETTERAZUREMCP_CREDENTIAL`) with fixed values; invalid values fail at startup with a clear message.                                                                              |
| Users with only **resource-level** access get 403: the server assumes subscription-level context.                                                                                                                                                                            | [microsoft/mcp#1655](https://github.com/microsoft/mcp/issues/1655)                                              | **Gap to verify.** Resource tools call ARM by resource ID, which respects resource-level RBAC. Resource discovery (Resource Graph, subscription list) has not been tested with resource-level-only access (W3).       |
| Multiple signed-in accounts: the wrong one is used.                                                                                                                                                                                                                          | [Troubleshooting guide](https://github.com/microsoft/mcp/blob/main/servers/Azure.Mcp.Server/TROUBLESHOOTING.md) | **Solved.** Tenant pinning, `azure_context` shows the identity in use, and `BETTERAZUREMCP_SUBSCRIPTIONS` restricts the server to chosen subscriptions (W4).                                                          |

## 4. Too many tools and oversized results

| Complaint                                                                                                                                            | Evidence                                                                                                                                                                         | BetterAzureMCP                                                                                                                     |
| ---------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `subscription_list` returned **44,221 tokens**, over Claude Code's 25,000-token limit.                                                               | [microsoft/mcp#428](https://github.com/microsoft/mcp/issues/428)                                                                                                                 | **Solved.** Every result is capped (12 KB by default). Lists are cut at item boundaries, with a note on how to narrow the request. |
| Namespace mode uses **2.9× more tokens** than consolidated mode, because help payloads are 23 KB.                                                    | [microsoft/mcp#3183](https://github.com/microsoft/mcp/issues/3183)                                                                                                               | **Solved.** 20 flat tools with no help round-trips; the whole tool list is about 5.8k tokens.                                      |
| Namespace mode routes to the wrong command ("failed to route correct mcp tool").                                                                     | [microsoft/mcp#3775](https://github.com/microsoft/mcp/issues/3775), [#3554](https://github.com/microsoft/mcp/issues/3554), [#3555](https://github.com/microsoft/mcp/issues/3555) | **Solved** (no routing layer).                                                                                                     |
| Microsoft's own evaluation: 2.4–5.3% of prompts pick the wrong tool, largely because tools overlap (App Service vs App Lens, Monitor vs workspaces). | [microsoft/mcp#3266](https://github.com/microsoft/mcp/issues/3266)                                                                                                               | **Partly.** CI guards against overlapping descriptions; the Claude-based selection eval exists but has not been run yet (W2).      |
| The 128-tool limit in VS Code is exceeded when Azure MCP runs next to other servers.                                                                 | [Troubleshooting guide](https://github.com/microsoft/mcp/blob/main/servers/Azure.Mcp.Server/TROUBLESHOOTING.md)                                                                  | **Solved** (20 tools).                                                                                                             |

## 5. Security and privacy

| Complaint                                                                                                                                                                                                            | Evidence                                                                                                                                                | BetterAzureMCP                                                                                                                                                                                                                                                                        |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Key Vault secrets exfiltrated by prompt injection.** A malicious instruction stored in data the user asked about led the agent to chain `extension az` → list vaults → `keyvault secret get`, and leak the values. | [HN discussion](https://news.ycombinator.com/item?id=44547907), [CodeIntegrity write-up](https://www.codeintegrity.ai/blog/azure) (via search excerpts) | **Solved for this chain.** No tool reads secret values, no generic CLI passthrough exists, and write/`listKeys`-style calls are blocked at the HTTP layer. Prompt injection in general is mitigated: untrusted text is marked, and text addressed to an AI assistant is flagged (W1). |
| **CVE-2026-32211** (CVSS 9.1): missing authentication in the Azure MCP Server's network mode allowed unauthenticated information disclosure.                                                                         | [MSRC](https://msrc.microsoft.com/update-guide/vulnerability/CVE-2026-32211), [GHSA-5w7p-v6h9-q8c5](https://github.com/advisories/GHSA-5w7p-v6h9-q8c5)  | **Solved by design.** stdio only; the server opens no network port. Any future HTTP mode must require authentication from day one.                                                                                                                                                    |
| An RSAC 2026 demo ("MCPwned") showed remote code execution through Azure MCP.                                                                                                                                        | [MCPProxy blog](https://mcpproxy.app/blog/2026-03-27-mcpwned-rsac-azure-rce/) (title and search excerpt only)                                           | **Solved by design.** No code execution, command generation or CLI passthrough tools.                                                                                                                                                                                                 |
| An independent scan scored Azure MCP 45/100 ("Risky") with 7 critical or high findings.                                                                                                                              | [AgentSeal](https://agentseal.org/mcp/azure) (via search excerpt)                                                                                       | Worth running the same scanner on BetterAzureMCP once published (W6).                                                                                                                                                                                                                 |
| **Telemetry is on by default** and sent to Microsoft; opt out with `AZURE_MCP_COLLECT_TELEMETRY=false`.                                                                                                              | [GitHub MCP Registry entry](https://github.com/mcp/com.microsoft/azure) (via search excerpt)                                                            | **Solved.** No telemetry code at all; outbound hosts are allowlisted and tested.                                                                                                                                                                                                      |

## 6. Depth of coverage

| Complaint                                                                                                                       | Evidence                                                                                    | BetterAzureMCP                                                                                                                                                                                                                                                |
| ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| "Some services still feel shallow": Functions only lists functions; **AKS lists clusters but doesn't interact with workloads**. | [ChatForest review](https://chatforest.com/reviews/azure-mcp-servers/) (via search excerpt) | **Solved for debugging.** `azure_aks_workloads` and `azure_aks_pod_logs` read live pod status, events and logs. Functions are covered through `azure_appservice_overview`, `azure_appinsights_*` and logs. Invoking or deploying is out of scope (read-only). |
| The Microsoft stack is fragmented across 18+ separate MCP servers.                                                              | Same review                                                                                 | Out of scope. We deliberately cover one job: debugging Azure applications.                                                                                                                                                                                    |

## Work items

Each item closes a **Gap** or **Partly** above.

| Item                                | Status                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **W1. Prompt-injection hardening.** | **Done.** Results with free text (logs, traces, events, tags, change records) are prefixed with an untrusted-content note. Every result is scanned for text addressed to an AI assistant, which adds a warning naming where it was found. The server instructions tell the model never to follow instructions in results. `SECURITY.md` documents why the server offers no exfiltration channel.                            |
| **W2. Tool-selection evaluation.**  | **Built; first run pending.** 55 realistic prompts in `eval/tool-selection.json`. CI checks for free that every tool is covered and that no two descriptions overlap too much (currently at most 0.18, limit 0.25). `npm run eval:tools` (or the manual **Tool-selection eval** workflow) measures real selection accuracy with Claude and fails below 95%. It needs Anthropic API credentials, so it has not been run yet. |
| **W3. Real-tenant validation.**     | **Tooling done; run pending.** `npm run live-check` exercises every tool against real resources in your tenant and prints a pass/fail table. It needs an Azure login, so it has not been run yet. Include an account with only resource-level Reader access.                                                                                                                                                                |
| **W4. Subscription scoping.**       | **Done.** `BETTERAZUREMCP_SUBSCRIPTIONS` limits the server to chosen subscriptions. A pipeline policy refuses any request naming another subscription and any Resource Graph query not limited to them; `azure_context` and `doctor` show only the configured subscriptions.                                                                                                                                                |
| **W5. Soak test.**                  | **Done.** `npm run soak` runs in CI: 16,500 calls against the built server with its heap capped at 64 MB, failing if memory grows or the server runs out of heap (verified against a deliberately leaking build). The server also has a memory watchdog: above `BETTERAZUREMCP_MAX_MEMORY_MB` (default 1024) it logs the reason and exits, so a bug can never take the whole machine down.                                  |
| **W6. Independent security scan.**  | **Partly.** CodeQL (security-extended queries) and `npm audit` now run in CI. The external scan behind the 45/100 score for Azure MCP can only run once the package is published.                                                                                                                                                                                                                                           |
| **W7. Client smoke tests.**         | **Checklist done; checks pending.** `docs/clients.md` has a five-minute manual check for each client and a table of results. No client has been checked by hand yet.                                                                                                                                                                                                                                                        |
